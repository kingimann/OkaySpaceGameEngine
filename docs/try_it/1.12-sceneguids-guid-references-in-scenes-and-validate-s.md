## 1.12-sceneguids. GUID references in scenes, Pool.* names, Validate Scene

**What it is.** (1) A scene saved by the editor under an `Assets` folder now carries a small `assetguid` table, so if you rename or
move a texture or sound in Explorer (without the editor) the scene finds it again when you open it. (2) Scripts can write
`Pool.Get(...)`, `Pool.Release()`, `Pool.Prewarm(...)`, `Pool.Idle(...)` (the same as `pool_get` and so on). (3) File >
Validate Scene lists scene problems in the Console.

**Steps.**
1. Open the editor, open or create a project, put a sprite using `Assets/art/hero.png` in a scene and press Ctrl+S.
   Open the `.okayscene` in a text editor: a line `assetguid <32 letters and digits> "art/hero.png" ...` is right under the first line.
2. Close the scene. In Explorer rename `hero.png` to `knight.png` and move `hero.png.okaymeta` with it (give it the same new name).
3. Open the scene again. The Console says "1 moved or renamed asset path(s) repaired" and the sprite still shows; the old file is
   kept as `<scene>.okayscene.bak`. Delete the picture and its `.okaymeta` and open again: the Console lists it as a broken reference.
4. In a script write `Pool.Prewarm("Bullet.okayprefab", 8)` in `start` and `Pool.Get("Bullet.okayprefab", 0, 0)` to fire; press Play.
5. File > Validate Scene: the Console prints "no problems found" or one line per problem (missing assets, duplicate ids, scripts...).
   Set `OKAY_SCENE_GUIDS=0` before starting the editor to switch the GUID table off.

**What you should see.** The lines described above. Old scene files (no table) open exactly as before.

**Status.** `test_scene_guids` and `test_object_pool_audit` cover the logic on Linux. The editor hooks and the menu item were not
run on Windows or in a full editor build here.
