Internal note. Not a user guide. It stays off by default: not in the engine CMake, not in CI, and not in releases. The engine does not include it. Built only by `tools/okaycc/build.sh`. This is our own compiler. It is meant to replace GCC and Clang in the long run (owner, 2026-11-23); it is far from ready for that.

Every line is written here from the documents named below. No copied compiler source, no third-party libraries, no cryptography.

## Status

- The lexer, preprocessor, parser, and type checker work for a C subset (`void`/`char`/`short`/`int`/`long`, signed and unsigned, `typedef`, casts, pointers, arrays, structs, `sizeof` of a type or an expression, functions, control flow, `switch` with `case`, `default`, `break`, and fallthrough, function pointers and arrays of them, `enum`, `union`, and global initializers for arrays, structs, and strings). Diagnostics use the source file name and the line number.
- The intermediate form is three-address code. Integers, calls, control flow, pointers, arrays, globals, string literals, and structs are lowered. Object sizes follow the System V AMD64 data model: `char` 1, `short` 2, `int` 4, `long` and pointers 8. Struct fields are aligned to those sizes. A struct of 1 to 8 bytes is passed and returned in one register, 9 to 16 bytes in two registers, and a larger struct in memory. The caller passes a hidden pointer for a large return. Multi-dimensional arrays use the element size as the step. A pointer to the struct being defined carries that struct's fields.
- The x86-64 code generator emits System V assembly for that subset. Tests assemble it with the system assembler and link it with the system linker (`gcc`). Narrow integers are sign-extended when loaded. An `int *` steps by 4. A `char *` steps by 1.
- A call to `write` is the Linux write system call, so a program can print without a C library. The same programs are compiled with the system gcc and the exit code and standard output are compared.
- The whole test suite has been run with AddressSanitizer and UndefinedBehaviorSanitizer on the compiler (`SAN=1 tools/okaycc/build.sh`). That run was clean.
- `long double` is accepted as `double`. A C++ subset has started. It accepts `namespace`, references, `bool` (one byte; a conversion or a store becomes 0 or 1), `nullptr`, `new` and `delete` as calls to `malloc` and `free`, and a non-virtual member function defined inside a `struct`. A namespaced name and a member function are mangled in the Itanium way for this subset (`_ZN1N1xE`, `_ZN1S3getEv`). `class`, virtual functions, templates, and exceptions are not accepted. okay-cc cannot compile its own lexer yet: that file includes C++ headers (`string`, `vector`, `cstdint`, and the rest of the standard library) which this compiler does not provide. `#pragma once` skips a file that was already included; any other `#pragma` is a warning and the line is ignored. `float` and `double` use SSE2 (`movsd`/`addsd` and the float forms). Arguments go in `xmm0`–`xmm7` and a result comes back in `xmm0`, per the System V ABI. The optimizer is a separate pass: it folds constants, propagates constants and copies across blocks, and deletes dead code. A linear scan keeps integer values in `rbx`, `r12`–`r15`, `rsi`, `rdi`, and `r8`–`r11`. A caller-saved register that is still needed after a call is stored to its stack slot and loaded back afterwards. Address-taken values stay on the stack. The ELF writer encodes x86-64 instructions itself. It writes a static executable and a relocatable object with a symbol table and `R_X86_64_PC32`, `R_X86_64_PLT32`, and `R_X86_64_64` relocations. `okay-ld` links those objects into one executable. A small libc (`write`, `exit`, `memcpy`, `memset`, `strlen`, `strcmp`, `strcpy`, `strcat`, `atoi`, `puts`, `printf`, and a coalescing free-list `malloc`/`free`/`realloc`/`calloc` on `brk`) is C compiled by okay-cc; `syscall` is the Linux syscall instruction. `printf` accepts a width, left adjustment, zero padding, `%ld`, `%u`, and `%f`. A variadic function saves the six integer argument registers and the caller sets `al` to 0. `include/stdarg.h` is for okay-cc; gcc keeps its own. Those paths do not use the system assembler or the system linker. The assembly path still does. A COFF writer emits an x86-64 relocatable object (file header, one or more sections, relocations, and a symbol table) from the PE/COFF specification. It is not connected to the code generator yet, and it shares no code with okayms. The driver is `okay-cc`.
- C++ classes (round 10, step 1). `class` and `struct` accept access labels (read, not enforced), constructors with member initializer lists, destructors, overloaded constructors (the checker picks by argument count, then by how well the types fit), single inheritance (the base fields are copied to the front of the derived class, so a base pointer is the same address), member functions defined outside the class, `this`, `extern "C"`, and a class name used as a plain type name. A local object runs its constructor at the declaration and its destructor at the end of the block, before `return`, `break` and `continue`, in reverse order. A class member and a base class run their own constructors and destructors (an implicit constructor or destructor is made when one is needed). `new T(args)` allocates and runs the constructor; `delete p` runs the destructor, then frees. Names follow Itanium C++ ABI 5.1: `_ZN3FooC1Ei`, `_ZN3FooD1Ev`. Data layout follows the Itanium ABI rule that a base which is "POD for layout" keeps its tail padding. Not done: copy and move constructors (an object is copied bytewise), `operator=`, global objects with constructors, arrays of class objects, access checking, multiple and virtual inheritance, exceptions, `goto` out of a scope that has objects with destructors. The new test group is `tests/progs_cpp/*.cpp`, run by `tests/test_cppdiff.cpp`: each program is compiled by okay-cc and by `g++ -std=c++17` and the exit code and output must match.
- C++ virtual functions (round 10, step 2). A class with a virtual function has a vtable pointer at offset 0 (`__vptr`). The vtable symbol is `_ZTV<class>`; it holds offset-to-top (0), the type-info pointer (always 0: there is no RTTI), then the function slots in declaration order, where a function that overrides a base function (with or without the word `virtual`) takes the base slot, and a virtual destructor takes two slots (complete-object `D1`, then deleting `D0`). A virtual call is the sequence `(*(void***)obj)[slot]` called with `obj` as the first argument. Each constructor stores its own class's vtable address after the base constructor ran, and each destructor stores it before its body, so a virtual call inside a constructor or destructor reaches that class's own function. `= 0` leaves a null slot (no `__cxa_pure_virtual`). The tests read the object's vtable by hand (offset-to-top, a slot called as a plain function) and compare with g++. Not done: a polymorphic class whose base is not polymorphic (the vtable pointer would shift the base), multiple and virtual inheritance, RTTI (`typeid`, `dynamic_cast`), covariant return types, `override` and `final` are read and ignored, a virtual call on an object expression with side effects is refused, and the `D2` base-object destructor.
- C++ templates (round 10, step 3). `template <typename T, class U, int N = 3>` before a function or a class. The template is kept as a range of tokens. A class template instance (`Box<int, 3>`) is made when it is named: the tokens are parsed again with each type parameter bound as a typedef and each value parameter as a constant, and the result is an ordinary class whose tag is `Box<i,Li3E>` (mangled as `3BoxIiLi3EE`; a `>>` closing two lists is handled). A function template called with explicit arguments (`maxOf<int>(a, b)`) is instantiated the same way. A function template called without arguments (`maxOf(a, b)`) is matched by the checker against the template's prototype (a pointer, reference or array pattern is walked, `T` binds to the argument type, an array decays), and then the file is parsed again with the new instance requests; this repeats until no request is new (at most eight rounds). Instance names are `_Z5maxOfIiEii` (name, `I` arguments `E`, parameter types; the return type is not encoded, so this is not the exact Itanium name). Also in this step: a struct can be copied through a pointer, a field or an index and can initialize a local (`T tmp = *a; *a = *b;`), and our `printf` prints `%ld` in 64 bits. Not done: a member function of an instance is compiled even if it is never used (C++ would skip it), specializations, overloaded function templates (one template per name), member templates, variadic templates, default arguments that are not a type or an integer, deducing a value parameter, member functions of a class template defined outside the class, class template argument deduction.
- C++ references, operators and copy constructors (round 11). `const` and `volatile` before a class name are read (a bare qualifier no longer ends the type). A function can take a reference parameter (`int &`, `const V &`): the caller passes the address of an lvalue of that type (or of a derived class) and the callee reads and writes through it; an argument that is not an lvalue is an error. A function can return a reference (`V &f()`): it returns the address (`return *this;`, `return p.x;`) and a call is an lvalue (`f().x = 5`, `f() += 2`, chained calls such as `c.inc().inc()`). A member operator is a member function named `operator+` and so on (Itanium operator codes `pl`, `mi`, `eq`, `aS`, `ix`, `cl`, `pp` ...); `a + b`, `a == b`, `a[i]`, `a(i)`, `a += b`, `-a`, `!a`, `++a` and `a++` (a dummy `int` argument) on an object whose class declares the operator are rewritten into the member call before checking. Only the left operand is tried, it must be a name, a member, an element or a dereference (not a call result), and non-member operators are not looked at. `T(args)` in an expression makes a hidden local constructed before the statement (its destructor does not run, which matches C++17 where such a temporary initializes the object it is used for). `T x = y;` and `T x(y);` run a user copy constructor `T(const T &)` when `y` is an lvalue of class T; `T x = f();` and `T x = T(...)` build in place. `d = a` calls a user `operator=`. A struct returned through any object expression (a temporary, `*p`, `a[i]`) is loaded correctly. A use of a class made before the class was complete (a member function that returns the class by value, `const V &` inside `V`) now takes its size and fields from the finished class. Not done: a conditional expression as an lvalue, a local of the class being defined inside one of its own member functions, conversion operators, `operator new`.
- C++ global objects and arrays of class objects (round 11). A global `G g(args);` or `G g;` of a class with a constructor or destructor is constructed first thing in `main` (in declaration order) and destroyed when `main` returns, at every `return` in it and at its end (reverse order). Only the globals declared before `main` in the same file are handled; a file without `main` never runs them (there is no `.init_array` in our linker yet). A local array `T a[N];` of a class with a constructor or destructor (constant size, no initializer, one dimension) constructs element 0 to N-1 and destroys N-1 down to 0, also at `return`, `break` and `continue`. Not done: an array member of a class, an array with an initializer, `new T[n]` and `delete[]`, a global array, a static local object, global objects in a file without `main`, `exit()` running the destructors.

- C++ by-value objects, implicit copy constructors and temporaries (round 12). The checker can now make hidden locals while it checks a statement; they are declared before that statement and destroyed after it (before the `return`, with the value kept first). Uses: (1) a class passed by value from an lvalue is copied into a hidden local by its copy constructor (or bytewise when it only has a destructor) and the copy is destroyed after the statement; a `T(args)` temporary or other object result passed by value initializes the parameter directly (no copy). (2) A reference parameter may bind to an rvalue: the value is copied into a hidden local (a `T(args)` temporary is used as it is). (3) A `T(args)` temporary is destroyed after the statement unless it initializes a variable, is returned or is passed by value. (4) An operator whose left operand is a call result or another operator expression (`a + b + c`): the left operand goes into a hidden local and the operator is called on it; an object result is kept in a hidden local too. (5) A class with no copy constructor of its own whose base or a member has one gets an implicit copy constructor (`T(const T &)`) that copies the base and each member with them (not made when the class has an array member, or a base without a copy constructor; those are still copied bytewise). `T x = y;` for any class with a constructor now goes through the checker, which picks the copy constructor for an lvalue and a plain copy for a temporary. The bodies of `if`, `while` and `for` are always blocks now. Not done: temporaries made in the condition of `while` or in the right side of `&&`, `||` and `?:` (they are destroyed after the whole statement, even if the operand did not run), a hidden copy for an argument of a function called through a pointer or by name that is not declared with a class parameter, `throw`, copies of arrays of objects.

- C++ conditional temporaries, global and static objects, `?:`, conversions and arrays (round 13). (1) Every hidden temporary that has a destructor now has a hidden flag, set to 1 by the expression that builds it and tested by the destructor call, so `a && f(T(1))`, `a || ...` and `c ? f(T(1)) : x` destroy only an object that was built. The temporaries of an `if` condition are destroyed before either branch (`{ c = cond; dtors; if (c) ... }`) and those of a `while` condition once per test (`while (1) { c = cond; dtors; if (!c) break; body }`). Temporaries of a `for` or `do` condition still die after the whole statement. A `T(args)` temporary is declared by the checker now, not the parser. (2) Global objects are built by `__okay_init_<file>` and destroyed by `__okay_fini_<file>` (made at the end of the file, so a global declared after `main` works); our linker and `compileToElf` call them around `main`, in link order, so a file without `main` works too (two-file test `tests/progs_cpp_multi`). A `static` local object is a real global plus a guard flag, built when control first reaches the declaration, destroyed before the globals. (3) `c ? x : y` with two lvalues of one class is an lvalue (`(c ? a : b).x = 1`). (4) Conversion functions: `operator int()`, `operator bool()` and the like, used for an object (an lvalue) in a condition, `!`, `-`, `+`, `~`, arithmetic and comparison, an assignment or initializer to a number, a number argument and a number return (the first conversion function of the class is used). (5) `new T[n]` and `delete[] p`: a class with a constructor or destructor goes through generated `__vnew_<T>` and `__vdel_<T>` (a count in front of the block when destructors must run, last element first); other types are `malloc` and `free`. Not done: a temporary in a `for` or `do` condition, a conversion function on a call result, a rvalue `?:` of two objects, `new T[n][m]`, a default constructor missing for `new T[n]` (then `__vnew_T` is not made and the program fails to link), an array of objects as a static local or with an initializer, `throw`.

- C++ round 14: loops, ++, templates. `do { } while (c);` (as `{ first = 1; while (first || c) { first = 0; body } }`, so `continue` reaches the test). Temporaries in a `for` condition die once per test. `(c ? a : b) = v`, `+=` and `++` on two lvalues of one type (as `*(c ? &a : &b)`). `new T[n]` for a class with no default constructor is an error message. `++` and `--` work on fields, elements, dereferences and globals (they were only accepted on local names), and `p++` on a pointer moves by the element size; `x += 1` on a global returns the new value. A member call on a result (`f().g()`) puts the result in a hidden local. A class template may name itself (`Node<T> *next` inside `Node<T>`), may be used as a temporary (`Pair<T, T>(v, v)`), and a function template may be given only its first arguments (`convert<int>(7)`, the rest deduced). Deduction sees through class template parameters (`length(Node<T> *)` from `Node<int> *`). `true` and `false` are accepted. A member of class type initialized from an object of its own class (`value(v)` with `T` a class) copies it. Tests: `tmpl3`, `tmpl4`, `cond2`, `incdec1`; the template programs (`tmpl3` is the explicit and deduced instances, nested `Box<Box<int> >`, a default type argument and a value parameter; `tmpl4` is deduction through `Node<T>`, `Stack<T, N = 3>`, `Pair<T, T>` return) were written before the fixes and failed first with the errors named above; `cond2` and `incdec1` failed first too (`'do' is not in this subset`, `not lowered`, wrong values).

## Exceptions (implemented, round 15)

Written from ISO/IEC 14882 [except]. This is NOT the Itanium C++ ABI exception model: objects thrown by code compiled with okay-cc cannot be caught by code compiled with g++ or libstdc++, and the reverse. It works only in a program linked from okay-cc objects and `lib/eh.c` (the runtime). It is on whenever a file contains `try` or `throw`; `okay-cc --eh` turns it on for a file without them (so that its destructor-bearing functions can be unwound through; link `lib/eh.c` whenever any object uses exceptions).

How it works. The runtime keeps a stack of records (14 longs each). An object with a destructor pushes a record when it is built and pops it when it is destroyed (locals, array elements, members and a base while a constructor runs, hidden temporaries). A `try` pushes a frame whose registers are saved by `__okay_setjmp` (an inline sequence: rbx rbp r12 to r15 rsp and the resume address; every named local of a function with a `try` is kept in memory, because a restore only brings back those registers). `throw e` copies e into runtime-owned memory (the copy constructor, or bytes) and calls `__okay_throw(object, "type names", destructor)`. The runtime pops records from the top: an object record runs its destructor, a handler record frees its exception, and the first try frame is entered with `__okay_longjmp`. The handlers of that try then test the type (`__okay_eh_match`: the thrown class and its bases by name; scalars and pointers must match exactly) and run the first that fits; when none fits the exception goes on (`__okay_eh_resume`) to the next try frame. A handler pushes a record of its own, so leaving it by a new throw frees the old exception, and `throw;` hands the same object on. When no try frame is left the program prints "terminate called after throwing an exception" on stderr and kills itself with SIGABRT, like g++.

Supported: throw of int, pointer and class values (a class by copy, including a `T(args)` temporary); `catch (T)`, `catch (T &)`, `catch (Base &)`, `catch (T *)` (exact pointer type), `catch (...)`; rethrow; nested try; try left by `return`, `break` and `continue`; destructors of locals, array elements, hidden temporaries (by-value argument copies, references bound to temporaries, `T(args)`, results of operator chains) and partly built members and bases run in reverse order during unwinding. Tests (compared with g++): `exc1` (types, handlers, rethrow, nesting), `exc2` (unwinding, constructors that throw, arrays, temporaries), `exc3` (uncaught), `exc4` (try left by return, break, continue; handler that throws; pointer thrown; throw in a loop).

Not supported: exception specifications and `noexcept` checks, `std::exception` and the standard library, a `return` inside a constructor body in a class with destructible members (an error says so), an object allocated by `new` whose constructor throws is not freed, a pointer catch that needs a derived-to-base conversion, throw from inside a destructor while unwinding (terminate is not called), `goto` out of a try, `throw` in a `for` or `do` condition temporary's destruction order, objects thrown across code compiled without `--eh` (their destructor-bearing frames are not unwound; their destructors do not run), the assembler path (`--asm`) has no `__okay_setjmp`. Cost: every function that has an object with a destructor pays a record push and pop; a function with a `try` keeps its locals in memory.
