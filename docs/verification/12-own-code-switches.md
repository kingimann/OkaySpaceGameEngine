# Verify: Own-code switches (off by default)

Our own replacements for third-party code. Every one is off by default and switched on by an environment variable.

Generated by `scripts/gen_verify_checklist.py` from the feature map and `docs/verification/steps/OC.md`; do not edit by hand. Read the [guide](README.md) first (legend and how to report).

Areas: 40. Rows ids start `V-OC-`. `V-OC-S<area>` rows are smoke tests built from the map; `V-OC-NNN` rows have written steps.

- [ ] **V-OC-001** Startup stack line (default)
  - **Map:** 40, 37. **Where:** editor, Help menu
  - **Steps:**
    1. Start `Tools\OkayEngine.exe` with no variables.
    2. Open **Help > About OkaySpace** and read the stack line.
  - **You should see (expected, not yet seen on Windows):** `[okay] stack: platform=sdl2 http=winhttp readers=ufbx+assimp crypto=libsodium ui=imgui` (the readers part may differ). `crypto=` must say libsodium in every release.
  - **Known partial:** a GUI program may not print to the console; the About popup is the sure way.
  - **More:** [../../try_it.md](../../try_it.md)

- [ ] **V-OC-002** OKAY_OWN_STACK turns on the own readers
  - **Map:** 3, 40. **Where:** Command Prompt, then editor
  - **Steps:**
    1. Run `set OKAY_OWN_STACK=1` then `Tools\OkayEngine.exe`.
    2. Open **Help > About OkaySpace**.
  - **You should see (expected, not yet seen on Windows):** `readers=own(fbx,dae,3ds,...)` in the stack line instead of `ufbx+assimp`.
  - **Known partial:** `OKAY_OWN_STACK=1` does not select the own platform layer on Windows (on purpose) and does not include `OKAY_OWN_WAV`.
  - **More:** [../../own_stack_rollout.md](../../own_stack_rollout.md)

- [ ] **V-OC-003** One own reader: OKAY_OWN_OFF
  - **Map:** 3. **Where:** Command Prompt, then editor
  - **Needs:** a release that ships the `examples` folder (PR #887, not merged when this was written)
  - **Steps:**
    1. Run `set OKAY_OWN_OFF=1` then start `Tools\OkayEngine.exe`; read **Help > About OkaySpace** (`readers=own(off)+assimp`).
    2. Choose **File > Import Model...** and pick `examples/own_readers/cube.off`.
    3. Close the editor, start it again with no variable and import the same file.
  - **You should see (expected, not yet seen on Windows):** a white unit cube both times; only the About line shows which reader ran.
  - **Known partial:** no Console line says which reader read the file. A variable set to `0` wins over `OKAY_OWN_STACK=1`.
  - **More:** [../../own_off_reader.md](../../own_off_reader.md)

- [ ] **V-OC-004** Other own readers
  - **Map:** 3. **Where:** Command Prompt, then editor
  - **Needs:** a release that ships `examples/own_readers/README.txt` (branch `claude2/own-reader-samples`, not merged when this was written)
  - **Steps:**
    1. Pick a switch from `examples/own_readers/README.txt` (one per reader, for example `OKAY_OWN_PMX`), run `set OKAY_OWN_PMX=1`, then start `Tools\OkayEngine.exe`.
    2. Choose **File > Import Model...** and pick that switch's file (`examples/own_readers/rig.pmx`). For `cube.irr`, `cube.lws` and `rig.md5mesh` untick **Copy the file into the project's Assets** first.
    3. Press **Import**.
  - **You should see (expected, not yet seen on Windows):** the Import Model window lists what the README says (meshes, skeleton, clips), the shape appears, and the Console says `read by our own PMX reader`.
  - **Known partial:** nobody has opened these samples in a real editor window yet. NDO has no sample (its reader refuses every file). Assimp was not run on the samples, so the comparison import without the variable is unchecked.
  - **More:** [../../try_it.md](../../try_it.md)

- [ ] **V-OC-005** Own WAV decoder
  - **Map:** 7. **Where:** Command Prompt, then editor
  - **Needs:** a release that ships the `examples` folder (PR #887, not merged when this was written)
  - **Steps:**
    1. Start the editor with no variable, open `examples/own_wav/own_wav_test.okayscene` and press Play.
    2. Close it, run `set OKAY_OWN_WAV=1`, start the editor, open the same scene and press Play.
  - **You should see (expected, not yet seen on Windows):** the old decoder gives a distorted, buzzy note; the own decoder gives a clean steady tone (about 440 Hz, A). Neither was heard by us.
  - **Known partial:** not part of `OKAY_OWN_STACK=1`; no startup-line entry; streamed large files still use the old parser. The release may not ship the example (PR #887).
  - **More:** [../../own_wav_decoder.md](../../own_wav_decoder.md)

- [ ] **V-OC-010** Own script editor (OkayUI CodeEdit) (steps unverified)
  - **Map:** 40, 13. **Where:** `Tools\OkayEngine.exe`, Script Editor window
  - **Steps:** (steps unverified: could not be confirmed against the code)
    1. Run `set OKAY_UI_BACKEND=okayui` then `Tools\OkayEngine.exe` (or, with `OKAY_DEV=1` set, open **View > Rendering & Performance > UI backend** and pick OkayUI (preview)). The script view follows the UI backend.

  - **Known partial:** never run in a real window; one caret only; no folding, no word wrap. Console and About lines also draw the Console, Crash Log and Audio Mixer with OkayUI.
