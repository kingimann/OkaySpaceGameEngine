# Model import: who reads which format

All model files come in through one door, `okay::ImportModel` (one merged mesh) and
`okay::ImportModelScene` (a node hierarchy with materials, skins and clips), both in
`okay/Render/ModelImport.hpp`. This page says which reader handles which format and how
the third-party reader (Assimp, optional) is kept behind a seam so it can be replaced one
format at a time. The plan is in `docs/own_code_roadmap.md`.

## Who reads what

| Format | Reader | Scene import (nodes, skins, clips) | Notes |
|---|---|---|---|
| `.gltf` `.glb` | our own, `Render/Gltf` | yes | always built in |
| `.fbx` | ufbx (vendored in `engine/third_party/ufbx`); Assimp only as a fallback for files ufbx rejects | yes | always built in |
| `.obj` (+ `.mtl`) | our own: `ReadObjFile` for scene import (one MeshRenderer per `usemtl`), `Mesh::LoadOBJ` for the merged-mesh path | materials only (no nodes) | always built in |
| `.stl` (ascii and binary) | our own, `ReadStlFile`. Assimp first when built with `OKAY_USE_ASSIMP` unless `OKAY_PREFER_OWN_READERS` | one mesh per `solid` | in every build since this change |
| `.ply` (ascii, little and big endian) | our own, `ReadPlyFile`. Same Assimp rule as STL | one mesh | in every build since this change |
| `.dae` | Assimp when built with `-DOKAY_USE_ASSIMP=ON`. Our own reader, `ReadColladaFile`, sits beside it and is **off by default** (see below) | yes (hierarchy, skins, matrix animation) | without Assimp and without switching ours on, `.dae` fails with a message saying how to switch it on |
| `.3ds` | Assimp when built with `-DOKAY_USE_ASSIMP=ON`. Our own reader, `Read3dsFile`, sits beside it and is **not ready and off by default** (see below) | yes (one node per object; no keyframes) | without Assimp and without switching ours on, `.3ds` fails with a message saying how to switch it on |
| `.blend` `.x` `.md5mesh` `.smd` `.ms3d` `.lwo` `.dxf` `.off` `.ac` `.b3d` `.3mf` `.amf` `.ase` `.x3d` `.md2` `.md3` `.mdl` `.bvh` and the rest of Assimp's list | Assimp, only when built with `-DOKAY_USE_ASSIMP=ON` | yes (hierarchy, skins, clips) | without Assimp these fail with `ok = false` |

`ImportableExtensions()` lists what the current build reads; the editor's file pickers use it.

## The seam

`okay/Render/ModelData.hpp` holds our own result type, `ImportedModel` (nodes, mesh parts, materials, bone
weights, clips) and the one entry point `ImportModelData(path, out, backend, flatten, err)`.
Assimp's own headers are included in exactly one file, `engine/src/Render/ModelImportAssimp.cpp`
(compiled only with `OKAY_USE_ASSIMP`); it turns an `aiScene` into an `ImportedModel`.
`ModelImport.cpp` builds meshes and scenes from `ImportedModel` only (`MergeModelMeshes`,
`BuildSceneFromModel`), so no caller touches an Assimp type.

Choosing a backend, per format (`.obj`, `.stl`, `.ply`, `.dae`, `.3ds` have one of ours):

* Build time: `-DOKAY_PREFER_OWN_READERS=ON` makes STL and PLY use our readers first, with Assimp as the fallback when ours rejects a file.
* Run time: `okay::SetImportBackend(".stl", ImportBackend::Own)` (or `Assimp`, or `Default`; `"*"` sets every format). `EffectiveImportBackend(".stl")` says what will run. Set it at start-up, not while another thread is importing.
* **Collada is opt-in.** Unlike STL and PLY, our `.dae` reader never runs unless asked: run-time `SetImportBackend(".dae", ImportBackend::Own)`, else the environment variable `OKAY_OWN_COLLADA=1` (`=0` forces it off), else the CMake option `-DOKAY_OWN_COLLADA=ON`. Switched on, it is tried first and Assimp (when built) is the fallback for files it rejects. Without Assimp and without the switch nothing reads `.dae`, as before. `ImportableExtensions()` lists `.dae` only while ours is on or Assimp is built.
* **3DS is opt-in the same way, and not ready.** Our `.3ds` reader never runs unless asked: run-time `SetImportBackend(".3ds", ImportBackend::Own)`, else the environment variable `OKAY_OWN_3DS=1` (`=0` forces it off), else the CMake option `-DOKAY_OWN_3DS=ON`. None of the Collada switches affect it and its switches do not affect Collada. Switched on, it is tried first and Assimp (when built) is the fallback for files it rejects. Without Assimp and without the switch nothing reads `.3ds`, as before; `ImportableExtensions()` lists `.3ds` only while ours is on or Assimp is built. It is off because it has only been checked against fixtures we wrote ourselves, never against files from real exporters.
* The default is unchanged where Assimp was used before: with Assimp built, STL and PLY still go to Assimp; without it, they now go to our readers (before, they failed). OBJ has never gone through Assimp.

## What our readers do

* **OBJ + MTL**: `v` `vt` `vn` `f` with negative indices and `v//vn`; polygons fan-triangulated; one part per `usemtl`. From the `.mtl`: `Kd`, `Ke`, `Ns`, `Pm`, `Pr`, `map_Kd`, `map_Bump`/`bump`/`norm`, `map_Ks`/`map_Ns`; texture options (`-s`, `-o`, `-bm` ...) are skipped; a missing `.mtl` is not an error. UVs are kept as written (like `Mesh::LoadOBJ`).
* **STL**: ascii or binary (told apart by the size rule, so a binary file whose header says "solid" still works). Vertices are welded per position and normal; the file's facet normal is used, or the winding's when it is zero.
* **PLY**: `x y z`, `nx ny nz`, `s t` / `u v` / `texture_u texture_v`; list `vertex_indices`; other elements and vertex colours are skipped. UV `v` is flipped like the other bottom-up formats. Without normals, smooth normals are generated (what Assimp's `GenSmoothNormals` does).
* All three: every read is bounds-checked, element counts are checked against the bytes left before anything is allocated, indices are range-checked, non-finite numbers are rejected, files over 512 MiB are refused. They return `false` with a one-line message.

* **COLLADA 1.4 / 1.5** (`engine/src/Render/ColladaReader.cpp`, off by default): own bounds-checked XML parser (entities, CDATA, comments, namespaces; no external entities are ever fetched; nesting, element count and size are capped). Reads `triangles`, `polylist` and `polygons` (fan-triangulated, one part per primitive element, vertices welded per position+normal+uv, smooth normals generated when the file has none, `<ph>` outer ring only); materials from the effect (`phong`/`blinn`/`lambert`/`constant`: diffuse colour or texture, emission, shininess, specular texture, a `<bump>` texture as the normal map; sampler, surface and image chains and `file://` / `%20` / backslash paths resolved next to the file); the node tree (`matrix`, `translate`, `rotate`, `scale`, `instance_node`; node names are the ids, as skins and animations name them); skins (the four strongest weights, renormalised; the bind shape matrix is folded into the inverse bind matrix; joints found by sid, within the `<skeleton>` subtree first); animations (every channel names a transform element of a node by its `sid`: a whole `matrix`, `translate`, `rotate` or `scale`, or one component such as `location.X`, `rotationZ.ANGLE`, `translate(1)`, `mat(1)(3)`; `node/transform` also replaces the whole local matrix when the node has no element with that sid). All channels of a node are merged: the element values are sampled at the union of the channels' key times, recomposed into the node's local matrix and decomposed into position, rotation and scale keys. `INTERPOLATION` is read per key: `LINEAR` and `STEP` are honoured (a step is written as a hold key just before the next key, 0.1 ms ahead, because our clips only interpolate linearly); any other name (`BEZIER`, `HERMITE`, `CARDINAL`, `BSPLINE`) is read as `LINEAR` and reported in the notes. A rotation segment of more than 90 degrees is split so the clip's quaternion interpolation cannot take the short way round. Top-level `<animation>` elements that hold other animations are one clip each; plain top-level animations (one per bone or property) are merged into one clip named `animation` (or by name when there is only one). The root node carries the unit scale and the rotation that makes +Y up (`Z_UP` and `X_UP` files). UV `v` is flipped like the other bottom-up formats. Flattened import (`ImportModel`, the merged-mesh path) bakes every transform into the vertices and returns no skins or clips.
* **What a reader did not read is said.** `ImportedModel::notes` lists it one line each, and `ImportModelData` logs every line as a warning. For Collada that covers: lines, line strips, triangle strips and fans, geometry that is not a mesh, vertex colours, UV sets after the first, morph (blend shape) controllers (the base mesh is imported), `<skew>` and `<lookat>`, animation channels whose target element or sid is not found, whose value count does not match, or whose keys are out of time order, interpolation other than LINEAR and STEP (read as linear), cameras and lights, malformed skins (the mesh is then imported unskinned), vertices with more than four weights, and skin joints that are not nodes of the scene.

* **3DS** (`engine/src/Render/ThreeDsReader.cpp`, not ready, off by default): own chunk reader (2-byte id, 4-byte little-endian length that counts the 6 header bytes). Every chunk length is checked against its parent and the buffer (at least 6, never past the parent), strings must be terminated, counts are checked against the bytes in their chunk before anything is allocated, vertices and faces are capped at 4 million each over the whole file, objects and materials at 100000, non-finite numbers are rejected, a face index past the vertex list is rejected, and a file shorter than its main chunk (any truncation) is rejected. The reader descends only the fixed chunk grammar (main, editor, object, mesh, face list, material group; at most six levels) and skips every other chunk by its length, so there is no recursion to cap. Reads: object name (`0x4000`), triangle mesh (`0x4100`), vertex list (`0x4110`), face list (`0x4120`; three indices and a flags word that is not used) with material groups (`0x4130`, resolved by name after the whole file is read, so a material defined after its object works; the first group to claim a face wins) and smoothing groups (`0x4150`), UVs (`0x4140`), the local-axes matrix (`0x4160`), materials (`0xAFFF`: name, diffuse colour, shininess, transparency, diffuse / specular / bump texture files with UV scale and offset; colour chunks `0x0010` and `0x0013` are floats, `0x0011` and `0x0012` bytes, floats preferred) and the master scale (`0x0100`). The file's vertices are in world space and `0x4160` holds the object's own axes and origin: the vertices are put into that local space and the matrix goes on the object's node, so world positions equal the file's and the object keeps its own orientation and pivot. A matrix that is singular, mirrored or sheared cannot sit on a node: that object keeps file-space vertices on an identity node, said in the notes. The root node carries the master scale and the Z-up to Y-up rotation, file (x, y, z) to (x, z, -y), a proper rotation, so winding is kept. One part per object and material, one node per object that has faces. Normals follow the smoothing groups when the file has them (a corner is shaded by the faces around its vertex that share a group bit with its own face; group 0 is flat; vertices are split where normals differ; work per object is budgeted, past which the rest is shaded flat and said); with no smoothing chunk, vertices are welded by index and smooth normals are generated per position, like the PLY and Collada readers. UV `v` is flipped like the other bottom-up formats; a texture's scale and offset are baked into the UVs of the part that uses the material (`u * scale + offset`). Shininess is the percentage times 128, transparency lands in `diffuse.a` (the scene builder does not use it yet), texture names are resolved next to the file (backslashes become slashes). Flattened import bakes every transform and returns one root node.
* **What the 3DS reader did not read is said.** Notes (each line also logged as a warning) cover: keyframe data (`0xB000`: no animation, no object hierarchy, no pivots; objects are flat children of the root), lights, cameras, objects without faces, ambient and specular colours (read, but `ImportedMaterial` has nowhere to keep them), opacity / reflection / second / shininess / self-illumination maps, texture rotation, face groups naming an undefined material, faces in two groups, singular / mirrored / sheared object matrices, UV lists that do not match the vertex count, a bad master scale, bytes after the main chunk, and every other chunk by id (for example background, fog, viewport and version-like chunks the reader has no use for).

## Audit: who reads `.3ds` today

Checked on this tree before the reader was written (`git grep` for `3ds` in engine, editor, tests and docs): nothing in the engine reads the format except Assimp; the editor only lists `.3ds` in its file filters.

| Feature of the format | HAVE (before) | Now in our reader | GAP (still not done) |
|---|---|---|---|
| Reading `.3ds` at all | Assimp only, and only in a build with `OKAY_USE_ASSIMP`; none otherwise | `Read3dsFile` / `Read3dsBuffer`, off by default | not ready; not run on real exporter files |
| Vertices, faces, UVs | Assimp | yes (16-bit counts, so 65535 per object) | none known |
| Per-face materials, colours, shininess, transparency | Assimp | diffuse colour, shininess, transparency | ambient and specular colours are read and dropped; no opacity or self-illumination |
| Textures | Assimp | diffuse, specular, bump file names; scale and offset baked into UVs | rotation, mirror/tiling flags, tint and opacity maps, second diffuse map |
| Smoothing groups | Assimp | per-corner normals by group; flat for group 0 | none known; budget fallback to flat on adversarial meshes |
| Object matrix `0x4160` | Assimp | on the object's node (vertices put into local space) | non-decomposable matrices keep world-space vertices |
| Units and axes | Assimp (Z-up to Y-up, master scale) | root node: master scale, Z-up to Y-up | none known |
| Keyframes `0xB000`, pivots, object hierarchy | Assimp | not read, said in the notes | animation, hierarchy and pivots |
| Lights, cameras, fog, backgrounds | none in the seam (`ImportedModel` has no lights or cameras) | not read, said in the notes | all of them |
| Safety on malformed input | Assimp's own checks | bounds, chunk and count checks, size caps, truncation at every length and a mutation sweep, clean under ASan and UBSan | not run on a corpus of real files |

## Tests

`collada_reader` (`tests/test_collada_reader.cpp`): five hand-written fixtures (`two_materials.dae`, `zup_cm.dae`, `skinned_strip.dae`, `component_anim.dae`, `unsupported.dae`) covering triangles and polylist, two materials with the sampler/surface/image chain, node transforms checked as world-space points, `Z_UP`/`X_UP` and unit, polygon fan and generated normals, skin weights and bone names, matrix animation, per-component and float3 channels merged per node, STEP, the BEZIER note, the 270 degree split,  every note, XML entities/CDATA/namespaces, the opt-in switch (environment, run-time, `*`), merged-mesh and scene import. In a build with Assimp it reads the same files through both backends and compares part, vertex, triangle, bone and clip counts and world-space bounds. `model_readers_fuzz` (also built on its own under `-fsanitize=address,undefined` from `ModelReaders.cpp` + `ColladaReader.cpp`; clean) adds the Collada malformed-input cases and puts the four `.dae` fixtures into the truncation and mutation sweep.

`threeds_reader` (`tests/test_threeds_reader.cpp`, fixtures `one_triangle.3ds`, `two_materials.3ds`, `transformed.3ds`, `smoothing.3ds`, `unsupported.3ds` made by `tests/data/models/make_3ds_fixtures.py`): axis and unit conversion as world-space points, winding kept, flattened import, two materials with the byte and float colour forms, shininess, transparency, a texture with scale and offset baked into the UVs, the object matrix as a node transform with local-space vertices and the singular-matrix fallback, smoothing groups (welded and split vertex counts and normals, group 0, no chunk), every note, a material defined after its object, chunk-level malformed input (zero, short, overlong and 4-gigabyte lengths at every chunk offset, counts past their chunk, indices out of range, NaN, unterminated names, two vertex lists), truncation at every length of every fixture, the vertex, face and object caps, a 20000-deep skipped chunk nest, the opt-in switch (environment, run-time, `*`, independence from the Collada switches, `=0`), merged-mesh and scene import. In a build with Assimp it reads the same files through both backends and compares part and triangle counts and world-space bounds. `model_readers_fuzz` (also built on its own under `-fsanitize=address,undefined` from `ModelReaders.cpp` + `ColladaReader.cpp` + `ThreeDsReader.cpp`; clean) adds the 3DS fixtures to the truncation and mutation sweep and runs a separate 20000-iteration 3DS sweep that rewrites chunk lengths and counts (`OKAY_FUZZ_ITERS_3DS` changes the number). `ctest` also runs it in a build with `-DOKAY_OWN_3DS=ON`.

`model_readers` (`tests/test_model_readers.cpp`, fixtures in `tests/data/models/`): every format and encoding, ascii equals binary, MTL fields, malformed input, a deterministic fuzz sweep (every truncation of every fixture plus mutations; run it under `-DOKAY_SANITIZE=address,undefined`), the backend switch, scene import of a two-material OBJ. In a build with Assimp it also reads the same files through both backends and compares part, vertex and triangle counts, the triangles themselves (positions, normals, UVs), the OBJ materials, and, for the glTF rig fixtures in `tests/assets/rigs`, Assimp's bone, skinned-mesh and clip counts against the glTF reader's.

## Not covered yet (still Assimp-only)

Blender (`.blend`), DirectX `.x`, MD2/MD3/MD5/MDL, SMD, MS3D, LWO, DXF, OFF, AC3D, B3D, 3MF, AMF, ASE, X3D, BVH and the rest of the Assimp list. FBX stays on ufbx. PLY triangle strips, PLY/STL vertex colours, STL colour attributes, and OBJ free-form curves and surfaces are not read.

## Collada: not done, and not yet proven

Our reader is checked only against fixtures we wrote ourselves and, in an Assimp build, against Assimp on those same files. It has not been run on files from real exporters, so it stays off by default. Known gaps: no morph targets, no `lines`/`tristrips`/`trifans`, no vertex colours or second UV set, no embedded texture data, no physics, kinematics or `extra` techniques other than a bump texture, polygons with holes keep only the outer ring, polygons are fan-triangulated (right for convex ones only), BEZIER/HERMITE/CARDINAL/BSPLINE curves are flattened to straight lines between keys (tangents are ignored), STEP is approximated by a 0.1 ms ramp, rotation is interpolated as a quaternion between the sampled keys, not as the file's angle, so very dense or very fast rotations are only as exact as the key spacing, a target sid is matched against the first node with that id so instanced nodes share one animation, animated materials, visibility and camera or light channels are not read, no COLLADA 1.5 `<instance_effect>` parameter overrides, and normals under non-uniform scale in flattened mode use the plain upper 3x3 matrix.

## 3DS: not done, and not yet proven

Our reader is checked only against fixtures we wrote ourselves; it has not been run on files from real exporters, so it stays off by default and is **not ready**. Known gaps: no keyframes, hierarchy or pivots, no lights or cameras, ambient and specular colours dropped, no opacity, reflection, tint or second-diffuse maps, texture rotation ignored, 16-bit counts mean at most 65535 vertices and faces per object (a format limit), the shininess mapping (percentage times 128) and the choice to treat file vertices as world space are from the public format description and untested on real files, and in a build with Assimp the comparison only checks counts and world-space bounds on our own fixtures.

## Known inconsistency

`.obj` UVs are kept as written (v up) while FBX, PLY and everything Assimp reads are flipped to v down. This predates the seam (`Mesh::LoadOBJ` never flipped) and was left as is so existing OBJ imports do not change; the readers and the comparison test record it.
