## 1.11-assets. Asset cache budget, hot reload and stats

**What it is.** The engine's asset cache can now be given a memory limit (least recently used items are dropped first), reloads
an edited data file only when its bytes really changed, and reports its numbers. Audio clips, pictures and `.okaydata` files all
report into it. The limit is OFF by default (unlimited), so nothing changes until you switch it on.

**Steps.**
1. Open the editor and open any project with a few textures and sounds. Look at the bottom of the Project panel: the line
   "Asset cache: x MB (no budget) | hits ..., loads ..., evicted ..." (hover it for the full report).
2. Open the Console panel and type `assets`. You see the counters and the size of the "audio clips" and "textures" caches.
   Type `assets list` for every loaded asset.
3. Type `assets budget 1` (1 megabyte). Press Play or move around, then type `assets trim`: it says how many assets were dropped, and
   the Project panel line now reads "of 1 MB". Type `assets budget 0` to go back to unlimited.
4. Type `assets hot on`. Edit a `.okaydata` file that a script reads with `DataAsset` in another program and save it: the value updates
   without restarting. Save it again without changing anything: `assets` shows "reloads skipped (same bytes)" go up.

**What you should see.** Numbers in the Console and the Project panel footer; with a budget the total stays near the limit.

**Status.** The logic is covered by `test_asset_cache` (Linux). The editor line and Console command were compiled only if the
coordinator's CI says so; the Windows build was not run here.
