# Roadmap: replacing the third-party libraries with our own code

**Goal: removal.** Every third-party library in the build is to be replaced by our own code and then deleted from the repository, slowly. Our own replacement is not a permanent second option: it is the future default, and the library is a temporary fallback that goes away. The only things we keep on purpose are services our users publish on and connect through: **Steamworks** and **Photon** (see the last section).

Our replacements stay **off by default** until the owner declares them ready and bug free. "Ready" is the list of criteria below, all of which must hold; there is no partial credit and no date.

## How a library is removed

1. **Seam.** A thin interface of our own between the engine and the library, so no other code calls the library directly.
2. **Own backend, side by side, off.** Our implementation sits behind the seam, selectable by a CMake option and a run-time switch, and is tested. The library stays the default.
3. **Replacement criteria.** Every one of these must hold before the default flips:
   1. A real-file or real-use corpus passes (files from real exporters, real hardware, real sessions; not only fixtures our own scripts wrote).
   2. Platform tests pass on **Windows and Linux** (the platforms CI covers; macOS and the web where the library is used there).
   3. Soak or fuzz: fuzzing under ASan/UBSan for parsers, a long soak run for anything stateful, with no crash and no hang.
   4. No known bugs in our replacement.
   5. **Owner approval**, written down in the PR. Nobody else declares a replacement ready.
4. **Flip the default** in one release the owner approves, with a release note one release ahead. The library is still compiled and selectable with the old option for that one release.
5. **Delete** the third-party code, its CMake option, its FetchContent block and its CI download, **one release after the flip**. Then update this page and `docs/THIRD_PARTY.md`.

A step ships only when it is finished and tested; each step is one PR with an honest NOT DONE list. Nothing is declared ready on this page: the state column below is what the code does today.

## Order

1. **Real-file validation of our own FBX, COLLADA and 3DS readers.** *Done for one corpus* (Assimp's test directory, `docs/model_corpus.md`: 43 FBX, 26 COLLADA, 16 3DS, 3 BVH, 54 glTF/GLB, 28 OBJ, 8 STL and 12 PLY files; the files are referenced by a manifest, not copied; sanitizer, valgrind and MinGW-under-wine runs done, a run on real Windows is not). What is left: files from more exporters, kept as the manifest grows. This unblocks the ufbx and Assimp rows once the owner approves.
2. **Finish 3DS and BVH.** *Done, both off by default* (`docs/own_3ds_reader.md`, `docs/own_bvh_reader.md`): the readers, fixtures from scripts, hostile-input tests and a mutation fuzz under sanitizers, and a run on real files.
3. **Drop-the-rest Assimp announcement and removal.** Write the release note naming the dropped formats one release ahead, flip the defaults for FBX and COLLADA when their criteria hold, then delete Assimp and ufbx as in the removal steps.
4. **Windows work on the platform layer.** Test and finish the Win32 backend on real Windows; macOS and the web follow.
5. **OkayUI docking and IME**, then the **editor and launcher off SDL2 and Dear ImGui** (own 2D painter, own platform backend, panels ported one at a time, text-editor widget), then delete SDL2, Dear ImGui and `editor/vendor/`.
6. **libsodium last, after the outside review** (`docs/crypto_review_package.md`), together with the TweetNaCl port.

## Services we keep

Steamworks and Photon are services our users want to publish on and connect through, so they stay as optional integrations behind `okay::net` and the Steam service interfaces. Our own relay and matchmaking sit next to them as an option, not instead. Hosting (GitHub Releases, Supabase) is likewise a service, not a library.

Update this page and `docs/THIRD_PARTY.md` whenever a row changes.
