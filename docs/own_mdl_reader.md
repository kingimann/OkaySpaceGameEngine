# Our own MDL reader (`.mdl`: Quake 1 and Half-Life 1)

Status: **side by side, off by default** (`OKAY_OWN_MDL`, same rules as `docs/own_3mf_reader.md`). Assimp (when built) is still the only other reader of MDL files. Nothing was flipped. **Unverified against real files:** there is no `.mdl` file in this repository (nor under `assets/` or `tests/`), so every test below uses a file built by hand from the documented structure.

## What it is

`.mdl` is used by four unrelated binary formats. This reader does the two that are documented in the open and common in games:

- **Quake 1** (magic `IDPO`, version 6): one vertex-animated mesh.
- **Half-Life 1** (magic `IDST`, version 10): the "studio" model, with bones, body parts, textures and sequences.

**Not done: 3D GameStudio MDL3, MDL4, MDL5 and MDL7.** I did not write them: I do not have enough documentation of their layouts in hand to write them without guessing, and guessing a binary layout would give a reader that looks finished and is not. A file with those magics is refused with a message that names the format and says it is not supported, so with Assimp built the default backend still reads it. Also refused with their own messages: Half-Life sequence group files (`IDSQ`: animation only) and Half-Life 2 / Source models (`IDST` with version 44 to 49).

## What it reads

**Quake 1.** The header (scale, origin, counts, skin size), the skin list (a single picture or a group; only the sizes are used), the texture coordinates and the triangles. **The first frame** (a simple frame, or the first picture of a group) as one static part: position = byte * scale + origin. Texture coordinates by the documented seam rule: a vertex marked `onseam` of a triangle that does not face front takes `s + skinwidth / 2`; then `u = (s + 0.5) / skinwidth`, `v = (t + 0.5) / skinheight` (not flipped). Quake winds clockwise: the corner order is reversed. Vertices are welded on position and texture coordinate, smooth normals are generated (Quake's table of 162 normals is not used), and the root turns Z-up into Y-up. Further frames (the engine has no vertex animation) and the skin pictures (8-bit palette indices, no palette in the file) are not read; the material has no texture and a note says how many skins were skipped.

**Half-Life 1.** The bone table (name, parent, default position and Euler angles, the animation scales) becomes the node tree under a root that turns Z-up into Y-up; a parent loop is cut, nodes come out parent first and repeated names get a suffix. Euler angles are rotations about X, then Y, then Z (`q = qz * qy * qx`), checked by hand in the tests. For every body part the **first model** is read; every mesh is one part, with its triangle commands (a positive count is a triangle strip, a negative count a triangle fan; each vertex is a vertex index, a normal index and `s`, `t` in texels): vertices are welded on all four, and every vertex is stored in the space of its bone, so it is moved to the bind pose (`world(bone) * v`) and rigidly skinned to that bone (weight 1, inverse bind = inverse of the bone's world matrix). Strips and fans are unrolled with the usual alternating order and **reversed** (the model viewer of the game draws with clockwise front faces). Because that is an assumption, each mesh's winding is checked against the stored normals: when more than twice as many triangles face against the average normal of their corners as with it, the mesh is flipped back and a note says so. The texture table gives one material per texture (the name, no texture file: the pictures are embedded 8-bit palette images and are not extracted); a mesh's texture comes from the first skin family's table; `u = s / width`, `v = t / height`. Each **sequence stored in the file** (sequence group 0) is one clip: the first blend, frames at the sequence's frame rate, per bone a position and rotation key per frame from the run-length coded values (`value = bone default + raw * bone scale`; a channel with no data keeps the bone's default; a bone with no animated channel gets no channel). The run-length decoder walks the runs once per channel, so it costs time in proportion to the frame count.

## Not handled (each is a line in `out.notes`)

Quake: frames after the first, skin pictures and animated skin groups, the stored normals. Half-Life: the alternative sub-models of a body part, skin families after the first, the embedded texture pictures, a model whose textures live in a separate `<name>T.mdl` file, sequences in external sequence group files (`name01.mdl`), the second and later blends of a blended sequence, bone controllers, hit boxes, attachments, events, sounds, pivots and transitions. All of 3D GameStudio MDL3 / 4 / 5 / 7.

## Limits

File 256 MiB. Quake: 200,000 vertices, 400,000 triangles, 4,096 skins, 100,000 frames, skin size at most 16,384 x 16,384; every table must really lie in the file before anything is allocated. Half-Life: 1,024 bones, 1,024 body parts, 1,024 models per part, 4,096 meshes per model, 200,000 vertices and normals per model, 4,096 textures and sequences, 65,536 frames per sequence, 2,000,000 output vertices and triangles, 4,000,000 animation keys over all sequences, **one file-wide work budget** of 16,000,000 units (every triangle-command vertex read, good or bad, every command, every mesh and every vertex and normal of a model read), 4,096 meshes per file, and 1,000,000 bone entries over all parts (parts x bones: each part carries the bone list). A body part that names a model another part already named is read once (a note says so). Every offset and count is checked against the file size with 64-bit arithmetic (`long` is 32 bit on Windows) before use; an animation run of length 0 (which would never end) makes that sequence be skipped; floats must be finite and within 1e9.

## Tests and what was checked

- `mdl_reader` (1,431 checks): a Quake file (positions by hand, the seam rule per triangle, welded vertex count, reversed winding, Y-up root, notes), a skin group, a frame group first, a vertex byte of 255, 15 header refusals, **every truncation**; the four GameStudio magics, `IDSQ` and a wrong magic; a Half-Life file (node tree, bind pose positions by hand, texture coordinates, normals, winding flip against a +Z normal and no flip against a -Z normal, rigid skin, inverse binds, the four animation frames from two runs of the run-length data, the clip's times), Euler angles against a hand rotation, a strip of four vertices (the swapped second triangle), a fan, cyclic and self-parent bone loops, a parent outside the table, hostile values (-1, 0x7FFFFFFF, 0x80000000, 1,000,000) in every header count and offset and in 18 inner fields, version 44, a command list that runs off the file, external sequence groups, an animation offset past the file, an animation run of 0, 65,536 frames, every third truncation.
- `e4_hostile`: the largest Quake model the caps allow (200,000 vertices, 400,000 triangles) is read in 0.3 s using 77 MB; counts at, past and far past each cap; 4,096 sequences of 65,536 frames sharing animation data (refused by the key budget in 0.2 s, 138 MB); 70 triangle strips of 32,767 vertices (refused by the vertex budget, 228 MB); 4,096 meshes; then 4,000 mutations of each of four seed files (40,000 in the sanitizer run).
- **Mutation checks** (a deliberate bug put into a copy of the reader, the test must fail): seam rule inverted (2 checks fail), run-length index off by one (3), parent range check removed (1), winding check removed (1), Euler angle sign changed (1), odd strip triangle order changed (4). All were caught. (Two first attempts were *not* caught and the tests were strengthened: the seam rule was only tested for the existence of both texture coordinates, and the Euler formula only with rotations about Z. The threshold of the winding vote, `2 *`, is not mutation checked: only its removal is.)
- After an outside review: a file-wide work budget, a per-file mesh cap, a parts x bones cap and read-once models were added; the new `e4_hostile` cases (1,024 body parts sharing one model of 4,096 meshes that share one 32,767-vertex command list with bad indices; 4,096 parts x 1,024 bones) and the name-collision test fail or hang on the code before the fix.
- Sanitizers: clean under ASan, UBSan and float-cast-overflow with 40,000 mutations per seed. The sanitizer run found no reader bug; it did show that a test allocator must also count `operator new(nothrow)`, which `std::stable_sort` uses.

## Unverified and not done

Unverified: any real file (Quake's `.mdl` models, Half-Life's models such as the player and weapon models, Counter-Strike and mod models); the winding assumption (backed by the normals check, not by a file); `.mdl` files with several skin families; the colour of Quake's skins (not read); the Quake rule for `onseam` on files made by other tools; a Windows run. Not done: 3D GameStudio MDL3 / 4 / 5 / 7, embedded texture pictures, the other items above. Assimp was not run on anything here, so no comparison with it was made.

## Provenance (what this file was written from)

`MdlReader.cpp` was written from scratch for this project. **No document, header file or source was consulted while writing it**: the layouts of the Quake 1 model (the `mdl_t`, `stvert_t` and `dtriangle_t` records, the frame records, the seam rule for texture coordinates) and of the Half-Life 1 studio model (the `studiohdr_t` header of 244 bytes, the bone record of 112 bytes, the body part of 76, the model of 112, the mesh of 20, the texture of 80, the sequence description of 176, the triangle command stream, the skin reference table, the run-length coded animation values) and the Euler-angle to quaternion order are **recalled from memory** of the id Software and Valve SDK headers and the format notes built on them. Recollection cannot be audited, and none of it has been checked against a real file. The sizes were summed by hand in the comments of `tests/e4_fixtures.hpp`, and the tests only prove that the reader agrees with those same recollections. **No code from Assimp or any other importer was read, copied or ported, and no snippet from the web was used.** The test files are hand-built from the same recalled structures.
