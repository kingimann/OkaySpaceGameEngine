**Goal: removal.** Every third-party library in the build is to be replaced by our own code and then deleted from the repository, slowly. Our own replacement is not a permanent second option: it is the future default, and the library is a temporary fallback that goes away. The only things we keep on purpose are services our users publish on and connect through: **Steamworks** and **Photon** (see the last section).

The stages between "it exists" and "the library is deleted" (off, dogfood, opt-in, default on, removed), the gates for each, the proposed order and the `OKAY_OWN_STACK` dogfood switch are in `docs/status/own_stack_rollout.md`. **Which replacement could flip next, in what order, with a checklist per flip, and what blocks deleting each library: `docs/status/own_flip_proposal.md` (2026-11-15).**

**2026-11-23, owner: "i want our stuff to be on by default, all of them".** Every run-time switch below and every
compile-time own option that builds and passes its tests is now ON by default (the list and what stayed off: section "One place to
try our own parts at run time"). Cryptography is not part of this (rule 18: libsodium stays the default). The text that follows
describes the earlier rule: our replacements stayed **off by default** until the owner declared them ready and bug free. "Ready" is the list of criteria below, all of which must hold; there is no partial credit and no date.

## How a library is removed

1. **Seam.** A thin interface of our own between the engine and the library, so no other code calls the library directly.
2. **Own backend, side by side, off.** Our implementation sits behind the seam, selectable by a CMake option and a run-time switch, and is tested. The library stays the default.
3. **Replacement criteria.** Every one of these must hold before the default flips:
   1. A real-file or real-use corpus passes (files from real exporters, real hardware, real sessions; not only fixtures our own scripts wrote).
   2. Platform tests pass on **Windows and Linux** (the platforms CI covers; macOS and the web where the library is used there).
   3. Soak or fuzz: fuzzing under ASan/UBSan for parsers, a long soak run for anything stateful, with no crash and no hang.
   4. No known bugs in our replacement.
   5. **Owner approval**, written down in the PR. Nobody else declares a replacement ready.
4. **Flip the default** in one release the owner approves, with a release note one release ahead. The library is still compiled and selectable with the old option for that one release.
5. **Delete** the third-party code, its CMake option, its FetchContent block and its CI download, **one release after the flip**. Then update this page and `docs/status/THIRD_PARTY.md`.

## One place to try our own parts at run time (2026-11-18)

Launcher **Settings > Experimental** and editor **View > Rendering & Performance > Experimental: try our own code** list
the own parts that can be chosen without a rebuild, **all ON by default since 2026-11-23** (untick one to go back): OkayUI screens
(`OKAY_UI_BACKEND=okayui`), the OkayUI Inspector (`OKAY_UI_INSPECTOR=1`), the OkayUI own renderer (`OKAY_UI_OWN_RENDER=1`) (the own
WAV decoder had an item too until it became the only WAV reader, and the own HTTP client until it became the only client, 2026-11-25), and on Linux the own window layer
(`OKAY_PLATFORM_BACKEND=own`). The choice is saved in `own_switches.cfg` (`off=` lists what the person turned off; no file, or an
old file from the off-by-default version that has only an `on=` line, means everything on) and applied as environment variables at
the top of `main()`; a variable the person set wins (so `OKAY_UI_BACKEND=imgui` still opts out).

Compile-time own options turned ON by default on 2026-11-23 (root `CMakeLists.txt`, so the Windows release built by
`scripts/build-windows-dist.sh` gets them too): `OKAY_OWN_WAV` (since deleted: the own decoder is the only path), `OKAY_OWN_GLTF1`, `OKAY_OWN_OPENGEX`, `OKAY_OWN_MDL`, `OKAY_OWN_Q3BSP`
and `OKAY_OWN_HTTP` (Linux only; Windows keeps WinHTTP). The other own readers were already ON. Still OFF, and why:
`OKAY_OWN_NDO` (a seam that refuses every Nendo file; `.ndo` is dropped since Assimp was deleted on 2026-11-24), `OKAY_OWN_CRYPTO` and
`OKAY_OWN_STACK_CRYPTO_TEST` (rule 18), `OKAY_OWN_STACK` (a developer dogfood switch that releases refuse; everything it turns on
outside crypto is now on anyway), `OKAY_LAUNCHER_ON_OKAYUI` / `OKAY_EDITOR_ON_OKAYUI` (extra programs: no CI job builds them, the
editor one has never been built, and turning them on would add an unbuilt program to the release build), `OKAY_PLATFORM_BACKEND=own`
on Windows (the Win32 backend has never run on real Windows; the run-time item is Linux-only), and `OKAY_UI_DEFAULT_BACKEND` stays
`imgui` on purpose: the "OkayUI screens" switch (on by default) already gives OkayUI, and an okayui build default could not be turned
off from the screen. The table is `Items()` in `shared/OwnSwitches.hpp`: a new run-time seam
(okay::platform events, own ImGui renderer, okayui host) adds one line. Compile-time-only options and cryptography are not in
it. Try it: `docs/try_it/own-switch.md`.
