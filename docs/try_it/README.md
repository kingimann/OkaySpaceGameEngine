# How to add something to "Try it" (docs/try_it/)

`docs/try_it.md` (the page the owner reads) is **generated**. You never edit it. Each thing to try is one small file in
this folder, so two open PRs never touch the same file and never conflict. (Before, every change appended a row and a
section at the end of one big file, and every pair of PRs conflicted.)

## Add an entry (CLAUDE.md rule 4a)

1. `python3 scripts/gen_try_it.py --new 7zz "Short title"` creates `docs/try_it/7zz-short-title.md` (or copy any file here).
   Pick an id nobody uses; two PRs with the same id fail the check, which is the point.
2. Fill it in. The part between the `---` lines is the front matter:
   * `id:` the entry id (letters, digits, dot, dash). Entries sort by it read naturally: `7 < 7b < 7zh < 16`.
   * `row:` (optional) the one table line for the index at the top: `| id | What | Where to reach it in the release | Status |`.
     It must start with `| <id> |`.
   * `group:` (optional) `main` (default), `switches` (the "off by default" own-code section) or `appendix`.
3. Under the front matter write the section, starting with a heading (`## 7zz. Title`): what it is, the steps (what to
   open, click or press), what you should see, and what is verified and what is not. An entry needs a row, a section, or both.
4. Run `python3 scripts/gen_try_it.py --check-entries`. That is what CI runs on your branch.
5. **Do not commit `docs/try_it.md` in a feature PR.** Leave it alone. The coordinator regenerates and commits it with
   `python3 scripts/gen_try_it.py` when merging or releasing (the same moment they bump the version and add the
   `ROADMAP.md` and `dist/CHANGELOG.txt` rows). `python3 scripts/gen_try_it.py --check` says whether the page is current.

## Change or delete an entry

Edit or delete its file. Do not reuse the id of a deleted entry for something else.

## A conflict in docs/try_it.md

It should only happen if someone committed the generated page in a PR. The resolution is always the same and needs no
reading of the markers: `python3 scripts/gen_try_it.py && git add docs/try_it.md`. (Conflicts between two entry files are
real: the same entry was edited twice; resolve that one file normally, then regenerate.)

## Files here

* `_header.md`: the text above the index table (title, status words, "Where the files are"). Rarely changes; it is the one
  shared file, so edit it in its own small PR.
* `<id>-<slug>.md`: one entry each. The file name only has to be unique; the id decides the order.
* The generator is `scripts/gen_try_it.py` (own code, Python standard library only). Its tests are in
  `scripts/tests/test_try_it.py`.

`docs/status/UNFINISHED.md` rows and the feature map have the same append-at-the-end conflict. The feature map is already
generated by `scripts/gen_feature_map.py` (resolve it by running that script). `docs/status/UNFINISHED.md` is hand written; the
same split is possible but was not done in this change.
