# No duplicate code

The owner's rule (2026-11-22): "create a system so duplicates can't happen again", across the whole repository and
in every language. Audits found about 30 kinds of copies: two save systems, two input systems, three JSON readers and
about eleven JSON escapers, seven Base64 copies, about twenty inline FNV-1a hashes, four CRC-32 tables, dozens of
`Trim`/`Split`/`ToLower` helpers, seven noise copies, five tween systems, nineteen hand-written ActionList message
loops, a D3D12 shader pasted from D3D11, and movement code pasted between controllers. Other work removes those. This
page is about the guard that stops new ones.

## The four parts

1. **The shared code list**, [docs/engine/shared_code.md](../engine/shared_code.md). One row per job (hashing, CRC,
   Base64, JSON, noise, tweens, timers, saves, input, logging ...): the one file to use, its names, and an example.
   Look there first. If the shared one is not quite right, extend it. Never paste.
2. **The claim.** Every claim on issue #422 has an `Existing:` line that names the code you build on (see
   [collaboration.md](collaboration.md), section 3). `python3 scripts/find_existing.py <words>` writes that line.
3. **The check**, `scripts/dup_lint.py`. It runs in the `branch-lint` workflow on every push to every branch, on every
   push to main, and on pull requests from forks. A failure stops the PR.
4. **An optional pre-push hook**, so you find out before CI does: `bash scripts/install_hooks.sh` (this clone only,
   never global; remove with `--remove`; skip once with `git push --no-verify`).

## What the check does

`python3 scripts/dup_lint.py check` looks at what your branch adds compared with `origin/main`:

| Finding | Result |
|---|---|
| A block of 80 or more tokens (about 10 to 15 lines) that is an exact copy of code elsewhere in the tree, or of another block the branch adds in a different file. Whitespace, comments and `#include`/`import` lines do not matter. | **error** |
| A new telltale of a known helper (the FNV-1a constants, the CRC-32 polynomial, the Base64 alphabet, a hand-made `Trim`/`Split`/`ToLower`, a JSON escaper, a Perlin fade or table, a law-of-cosines IK solve, SplitMix/LCG constants, a DEFLATE table, the Back easing constant, HLSL text inside C++, the MinGW install block in a workflow) outside the file that owns it | **error** |
| A file whose count of such telltales goes up | **error** |
| `scripts/dup_baseline.json` grows | **error** (it may only shrink) |
| `dup-allow:` with no reason | **error** |
| `docs/engine/shared_code.md` names a file that does not exist (rows marked "planned" are skipped) | **error** |
| A block of 120 or more tokens that matches with the names changed (a renamed copy) | warning |

It reads every code file in the repository: C and C++ (engine, editor, launcher, player, shared, okayui, tools,
tests, platform, relay, steam, sandbox ...), C#, JS/TS, shaders (GLSL, HLSL, `.okayshader`), Python, shell,
PowerShell, batch, NSIS, YAML workflows, CMake, SQL, Lua, HTML and the engine's script graphs (`.okayvs`, `.okaybt`).
Tests are included: test harness code is shared through a helper header, not pasted. Markdown is not code and is not
searched for copies.

Left out, with the reason (the `EXCLUDE` list in the script): `engine/third_party/` and `editor/vendor/` (vendored
code), `okayui/probe/` (copies of Dear ImGui headers kept only to compare against), `editor/generated/` (written by a
script), `tests/wycheproof/` (third-party test vectors), `tests/data/`, `tests/golden/`, `tests/assets/`,
`tests/export/` (fixtures and golden data), `tools/okaycc/tests/progs*` (programs the compiler compiles),
`tools/okayms/stdinc/` (stand-in standard headers), and any file whose first lines say it is generated ("Generated by",
"do not edit", "exported using").

## How the copy search works (plain words)

Each file is cut into tokens (words, numbers and symbols), with comments and spacing thrown away, by a small
tokenizer for its language family. Words inside string literals are tokens too, so a shader pasted as C++ strings
is found. At points chosen by the content itself (about one token in six), the next 32 tokens are hashed. A copy
has the same content, so it gets the same points and the same hashes. Two equal hashes are then grown token by token
in both directions to find the full length of the match. A second, "loose" pass replaces every name with `$` and every
number with `0`, which finds copies whose variables were renamed; those only warn.

To stay fast, `check` only fully reads the changed files and the files that contain every word of some added block
(a file without those words cannot hold an exact copy of it). Very common windows (words that appear together in more
than 40 files, such as `auto const first`) are not used to pick files; the other windows of a real paste find it.
Renamed copies are looked for only in files that share three of the five rarest words of the block (best effort).

Why 80 tokens: on main there are about 3,450 exact pairs of 80 or more tokens, 6,990 of 60 or more and 12,600 of 50 or
more. Most matches under 80 tokens are 2 to 4 lines of the same call shape (long `push_back` lines, colour lerps,
setter rows). From 80 tokens up they are mostly real pasted helpers: the same `TestSetEnv`/`Slurp` test harness in
two reader tests, the same `TempDir` struct, the movement block in both character controllers. With 32-token hashes
and an anchor every 6 tokens on average, the chance that an 80-token copy has no anchor in its first 49 tokens (and
is missed) is about (5/6)^49, roughly 1 in 7,000.

## Silencing a real need

Some copies are right: a table that must match a file format spec, a test that must not depend on the code it
checks. Mark it and explain it in the PR:

```cpp
static const std::uint32_t kPoly = 0xEDB88320u;  // dup-allow: the test must not use the CRC it checks
// dup-allow-begin: the two shader stages must stay byte-identical for the D3D12 root signature test
...
// dup-allow-end
```

`dup-allow: <reason>` works on the line or the line above. The reason must not be empty.

## When a dedup lands: shrink the baseline

`scripts/dup_baseline.json` lists the telltales that exist today (rule, file, count). It is a ratchet: it may only go
down. When your PR removes copies, `check` prints "baseline can shrink" with the entries that went down. In the same PR:

```
python3 scripts/dup_lint.py scan --update-baseline
git add scripts/dup_baseline.json
```

Also move the row in [shared_code.md](../engine/shared_code.md) from "planned" to the real file.

## Commands

```
python3 scripts/dup_lint.py check                       # what this branch adds (CI runs this)
python3 scripts/dup_lint.py check --base origin/main --head origin/<branch>   # another branch, no checkout
python3 scripts/dup_lint.py scan --histogram --loose    # whole-tree report: rule hits, clone pairs, per language
python3 scripts/dup_lint.py scan --update-baseline      # rewrite the baseline (only after copies were removed)
python3 scripts/branch_lint.py dups                     # the same check through branch_lint
bash scripts/install_hooks.sh                           # optional pre-push hook for this clone
python3 scripts/tests/test_dup_lint.py                  # the check's own tests (also ctest: dup_lint_script)
```

Speed (measured on a shared, busy 4-core machine): `check` on a branch takes about 7 to 20 seconds depending on how much
it adds; `scan` of the whole tree (about 3,000 files, 48 MB) takes about 15 to 25 seconds; the rules alone take about 5
seconds. Nothing is cached and nothing is written to git.

## Limits

- A pasted block shorter than 80 tokens is not reported. A copy made only of very common words, or a table of numbers
  with no words, may be missed by `check` (but `scan` finds it).
- Renamed copies are found on a best-effort basis and only warn.
- The fingerprint rules are regular expressions: they can miss a copy written in an unusual way, and can match an
  unrelated use of the same constant (mark that with `dup-allow`).
